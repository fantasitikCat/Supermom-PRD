How We Know If Our Messages Work MA 消息追踪
我们如何知道消息是否真正有效

Every Email and WhatsApp message we send contains a campaign link. But do users actually click it? Do they visit the page? Do they convert? Right now, we cannot reliably answer these questions. This document explains how we fix that — and what it means for the business.
我们发出的每一封 Email 和每一条 WhatsApp 消息都包含活动链接。但用户真的点击了吗？访问了页面吗？完成了转化吗？目前，我们无法可靠地回答这些问题。这份文档解释我们如何解决这个问题，以及它对业务意味着什么。

    Our Solution — How It Works解决方案 — 原理说明

    2.1 The Big Picture 2.1 整体思路
    The core idea:核心思路： Every campaign link we send now automatically carries two types of tracking code: ma_ref (our internal tracking) and UTM parameters (for GA4 reports). Both are generated by the system — zero manual work for anyone. 我们发出的每条活动链接，现在自动携带两种追踪码：ma_ref（系统内部追踪）和 UTM 参数（用于 GA4 报告）。两者均由系统自动生成，任何人都不需要手动操作。
    2.2 What is ma_ref — Our Internal Tracking Code 2.2 ma_ref — 系统内部追踪码
    Think of ma_ref like a barcode on a parcel. The barcode tells the system where it came from, who it's for, and which shipment batch it belongs to. The customer never sees it — it works invisibly.

    ma_ref works the same way. It's an encrypted code attached to every campaign link. When a user clicks it, the system instantly knows: which user clicked, which Flow sent the message, which specific message step it was, and which channel (Email or WhatsApp). The code is fully encrypted — no personal data (name, phone, email) is ever visible in the URL.
    把 ma_ref 想象成快递包裹上的条形码。条形码告诉系统包裹从哪里来、发给谁、属于哪批货物。客户完全看不到它，它在后台无感运行。

    ma_ref 的原理完全一样。它是附加在每条活动链接上的加密码。用户点击后，系统立刻知道：哪个用户点击了、哪个 Flow 发送了消息、是哪个具体的消息节点、以及渠道是 Email 还是 WhatsApp。这个码经过完整加密——URL 中不含任何个人信息（姓名、手机号、邮箱）。
    What ma_ref carries — decoded by the system (invisible to users)ma_ref 携带的信息 — 由系统解码（用户不可见）
    2.3 UTM Parameters — What GA4 Uses for Reports 2.3 UTM 参数 — GA4 报告使用的数据
    While ma_ref is our internal system code, UTM parameters are the standard way GA4 and Google Analytics understand where traffic comes from. They are separate from ma_ref and serve a different purpose — they make your campaign data visible and filterable in GA4 reports.

    The key difference from today: UTM parameters used to be added manually by people — which meant inconsistent data, typos, and missing values. Now the system generates them automatically every single time, making the data completely reliable.
    ma_ref 是我们的系统内部追踪码，而 UTM 参数是 GA4 和 Google Analytics 理解流量来源的标准方式。它们与 ma_ref 相互独立，服务于不同目的——让活动数据在 GA4 报告中清晰可见、可筛选。

    与当前最大的区别：UTM 参数以前由人工手动添加——导致数据不一致、拼写错误、遗漏等问题。现在系统每次自动生成，数据完全可靠。
    UTM ParameterUTM 参数 Value (auto-generated)值（系统自动生成） What it means in GA4在 GA4 中的含义 Business value业务价值
    utm_source crm — fixed, system-set Identifies traffic as coming from our CRM / MA system. In GA4 Acquisition report, you can filter all sessions where source = crm. 标识流量来自我们的 CRM / MA 系统。在 GA4 流量获取报告中，可以筛选所有 source = crm 的会话。 Separates MA-driven traffic from organic, paid, and direct traffic in all reports 在所有报告中将 MA 驱动的流量与自然流量、付费流量、直接流量区分开来
    utm_medium whatsapp or email auto-set by channel Identifies the channel type. GA4 uses this to separate Email-driven sessions from WhatsApp-driven sessions in reports. 标识渠道类型。GA4 用此区分 Email 驱动的会话和 WhatsApp 驱动的会话。 Directly compare Email vs WhatsApp performance — clicks, conversions, drop-off rates 直接对比 Email vs WhatsApp 的表现——点击率、转化率、流失率
    utm_campaign MA Flow name — taken directly from the Flow's name in the system MA Flow 的名称 — 直接从系统中的 Flow 名称获取 e.g. onboarding_new_user_2026 Identifies which campaign (Flow) drove this traffic. GA4 shows performance broken down by campaign name — click rate, sessions, conversions per Flow. 标识哪个活动（Flow）带来了流量。GA4 按活动名称展示表现——每个 Flow 的点击率、会话数、转化数。 Compare performance across all Flows side by side in one GA4 report 在一张 GA4 报告中并排对比所有 Flow 的表现
    ⚠️ Important: Flow naming affects GA4 report clarity ⚠️ 重要：Flow 命名直接影响 GA4 报告的可读性
    Since utm_campaign is taken directly from the Flow's name, how you name your Flows determines how data appears in GA4 reports. A well-named Flow makes reports immediately readable. A poorly named Flow makes reports confusing and unusable.
    由于 utm_campaign 直接取自 Flow 的名称，Flow 的命名方式决定了 GA4 报告中的数据展示效果。命名清晰的 Flow 让报告一目了然，命名随意的 Flow 会让报告难以阅读和使用。

    2.4 Complete URL Example — What Is Actually Sent 2.4 完整链接示例 — 实际发出的链接长什么样
    When a user receives an Email or WhatsApp message, the campaign link they click looks completely normal. Behind the scenes, the system has automatically attached both ma_ref and UTM parameters. Here is what a real link looks like:
    当用户收到 Email 或 WhatsApp 消息时，他们点击的活动链接看起来完全正常。在后台，系统已自动附加了 ma_ref 和 UTM 参数。以下是一条真实链接的样子：
    https://welovesupermom.com/campaign/mothers-day
    ?ma_ref=aB3xK9mPqR2vLn7w ← internal tracking (encrypted, system only)
    &utm_source=crm ← GA4: traffic from CRM/MA system (auto)
    &utm_medium=whatsapp ← GA4: channel is WhatsApp (auto)
    &utm_campaign=promo_mothers_day_sg ← GA4: campaign = Flow name (auto)
    100% automatic — nobody manually writes this URL.100% 自动生成 — 没有任何人手动拼写这条 URL。 The business team sets the base landing page URL (e.g. welovesupermom.com/campaign/mothers-day). Everything after the ? is added by the system automatically at send time. This guarantees consistent, reliable, error-free data in every report. 业务团队只设置基础落地页 URL（例如 welovesupermom.com/campaign/mothers-day）。? 之后的所有内容由系统在发送时自动添加。这保证了每份报告中的数据始终一致、可靠、无误。

    CRM Team — One Important Action RequiredCRM 团队 — 一个重要操作说明

    📋 CRM Team Action Required 📋 CRM 团队操作要求
    WhatsApp templates with campaign links must use Dynamic URL buttons — not Static URL buttons.

    This is the only technical requirement for CRM. Here's the difference:
    包含活动链接的 WhatsApp 模板，必须使用动态 URL 按钮（Dynamic URL），不能使用静态 URL 按钮（Static URL）。

    这是 CRM 团队唯一的技术要求。区别如下：
    Dynamic URL vs Static URL — Why It Matters动态 URL vs 静态 URL — 为什么重要
    Dynamic URL is already the standard for most templates. This is a reminder to keep it that way — and make sure any new templates follow the same rule. 动态 URL 已经是大多数模板的标准。这里是提醒保持这一标准——并确保所有新建模板遵循同样的规则。
    What the system does automatically after CRM sets Dynamic URL:CRM 设置动态 URL 后，系统自动处理的事情： (1) Converts the base URL to a dynamic URL format → (2) Generates ma_ref token per recipient → (3) Appends UTM parameters from Flow name → (4) Submits template to Meta API → (5) Sends to users. CRM does not need to do any of steps 2–5. (1) 将基础 URL 转换为动态 URL 格式 → (2) 为每个收件人生成 ma_ref token → (3) 从 Flow 名称附加 UTM 参数 → (4) 提交模板至 Meta API → (5) 发送给用户。CRM 团队不需要处理第 2–5 步中的任何事情。

    Business Benefits业务价值

    5.1 Accurate Attribution — Know What's Working 5.1 精准归因 — 知道什么真正有效
    Attribution means knowing which message caused which outcome. With the combination of ma_ref (internal tracking) and UTM parameters (GA4 reporting), we can now answer questions that were previously impossible:

    "Our Day 3 WhatsApp reminder in the Onboarding Flow drove 340 registrations last month, with a 12% click-to-register rate. The Day 7 Email performed 40% better for paid users."
    归因是指知道哪条消息导致了哪个结果。通过 ma_ref（内部追踪）和 UTM 参数（GA4 报告）的结合，我们现在能回答以前根本无法回答的问题：

    "上个月，新手引导 Flow 中第 3 天的 WhatsApp 提醒带来了 340 次注册，点击注册率 12%。付费用户中第 7 天 Email 的表现比第 3 天 WhatsApp 高 40%。"
    5.2 Identity Stitching — Connecting the Same Person Across Sessions 5.2 用户身份拼接 — 跨会话识别同一个人
    Common scenario: A user receives our WhatsApp, clicks the link, browses anonymously for 10 minutes, then closes the app. Three days later they return directly and register.

    Without tracking: the WhatsApp click and the registration are two disconnected events.
    With ma_ref: the system remembers the WhatsApp click. When they register 3 days later, the system stitches the full journey together — "received WhatsApp → browsed → registered" — all attributed to the correct campaign.
    常见场景：用户收到我们的 WhatsApp，点击链接，匿名浏览 10 分钟后关闭了应用。三天后他们直接回来完成了注册。

    没有追踪时：WhatsApp 点击和注册是两个断开的事件。
    有了 ma_ref 后：系统记住了 WhatsApp 点击。当他们 3 天后注册，系统自动将完整链路拼接——「收到 WhatsApp → 浏览 → 注册」——全部归因到正确的活动。
    5.3 GA4 Analysis — What You Will See in Reports 5.3 GA4 分析 — 报告中你将看到什么
    All data flows directly into GA4. No new tools to learn. The UTM parameters make your campaign data appear as standard GA4 dimensions — source, medium, and campaign — that you can filter, compare, and build dashboards from.
    所有数据直接流入 GA4，无需学习任何新工具。UTM 参数让你的活动数据作为标准 GA4 维度显示——source、medium 和 campaign——可以直接筛选、对比并构建仪表盘。
