⭐ Executive Summary · 业务摘要
What is this document about?
这份文档讲什么？
A plain-language summary for business stakeholders
面向业务同事的通俗说明
When Aima sends a link to a user — through WhatsApp or a website chat widget — we currently have no way to know if that user actually clicked the link, visited the page, or converted. This document defines how we fix that, by attaching a small tracking code (aima_ref) to every link Aima sends. It also clearly defines who is responsible for each step and why, so no team is doing someone else's job.
当 Aima 通过 WhatsApp 或网站 Widget 向用户发送链接时，我们目前无法知道用户是否真的点击了链接、访问了页面、或完成了转化。这份文档定义了解决方案——在 Aima 发送的每条链接上附加一个追踪码（aima_ref）。同时明确每个团队负责哪一步以及原因，避免职责混淆。

Background 背景

背景

Aima is a conversational AI sending links to users via WhatsApp and a website widget. Currently, there is no mechanism to track whether users click those links or what actions they take afterward.

Aima 是对话式 AI，通过 WhatsApp 和网站 Widget 向用户发送链接。目前没有任何机制追踪用户是否点击了这些链接，以及点击后的行为。

6.1 Definition
6.1 定义
UTM Values Reference: All UTM values follow UTM-GOV-001 v1.2 — UTM Parameter Dictionary (B2C UTM Advisory aligned). Confirmed values: utm_source=aima, utm_medium=whatsapp, utm_term={rec_id}.
UTM 值参考：所有 UTM 值遵守 UTM-GOV-001 v1.2（已与 B2C UTM Advisory 对齐）。确认值：utm_source=aima、utm_medium=whatsapp、utm_term={rec_id}。

Why no UTM for website_widget? 为什么 website_widget 不加 UTM？

The user is already on the website. GA4 is already tracking their session. Adding UTM parameters would start a NEW GA4 session, breaking the existing attribution chain and causing double-counting. GA4 events are the correct tool for in-session behaviour.

用户已经在网站上，GA4 已经在追踪他们的 session。追加 UTM 参数会开启新的 GA4 session，破坏已有的归因链，导致重复计数。GA4 events 是追踪 session 内行为的正确工具。

7.1 字段结构

MA-Triggered Scenario — Handling Rule MA 触发场景处理规则

MA 触发场景处理规则

Industry Principle — Orchestration vs Execution: When MA System triggers Aima to send a message, MA is the Orchestration Layer (decision maker) and Aima is the Execution Layer (message sender). Tracking attribution follows the decision maker — therefore MA tracking parameters take precedence.
行业原则 — 编排层 vs 执行层：当 MA 系统触发 Aima 发送消息时，MA 是编排层（决策者），Aima 是执行层（发送者）。追踪归属跟随决策者——因此 MA 追踪参数优先。
⚠️ MA Engineer + Aima Engineer alignment required: This rule requires both engineers to agree on the interface — how MA passes tracking parameters to Aima. Refer to PRD-TRK-007 S9 for MA UTM rules. Refer to UTM-GOV-001 v1.2 for confirmed UTM values: MA uses utm_source=crm + utm_medium=messaging; Aima uses utm_source=aima + utm_medium=whatsapp.
⚠️ MA 工程师 + Aima 工程师需要对齐：此规则需要两位工程师就接口达成一致——MA 如何将追踪参数传给 Aima。MA UTM 规则参考 PRD-TRK-007 S9。允许的 UTM 值参考 UTM-GOV-001。

Why Aima owns this 为什么由 Aima 负责

Aima is the only system with full conversation context (session, message, channel) at the exact moment of sending. No other system can inject the correct parameters — only the system that holds the conversation knows what to attach.

Aima 是发送时唯一拥有完整对话上下文（session、消息、渠道）的系统。没有其他系统能注入正确的参数——只有持有对话的系统才知道要附加什么。

  • 存储上下文映射：aima_ref → conv_id / msg_id / user / runtime_source

Why Aima Backend owns this 为什么由 Aima Backend 负责

Token generation MUST be server-side to prevent user tampering and ensure auditability. Backend is the only system that can safely map opaque tokens to real user identity without exposing PII to the browser or to Aima itself.

Token 生成必须在服务端，防止用户篡改并确保可审计。Backend 是唯一能安全地将 opaque token 映射到真实用户 identity 的系统，而不向浏览器或 Aima 本身暴露 PII。

  • Pass page context: page_url, ga_session_id, ga_client_id

Why Frontend owns this 为什么由 Frontend 负责

Frontend is the ONLY system that knows the current page's GA4 session and URL when the Widget initialises. Without this context, Aima cannot determine its operating channel — and would default to the wrong tracking strategy.

Frontend 是 Widget 初始化时唯一知道当前页面 GA4 session 和 URL 的系统。没有这个上下文，Aima 无法判断自己的运行渠道，会采用错误的追踪策略。

🚫 Forbidden: GTM must NOT verify, decode, or parse aima_ref. GTM must NOT execute any identity resolution logic. 🚫 禁止： GTM 禁止验证、解码或解析 aima_ref。GTM 禁止执行任何 identity 解析逻辑。
Why GTM's role is limited 为什么 GTM 职责受限

GTM runs in the user's browser. Any logic executed there is visible and manipulable by end users. Identity resolution and token verification must remain on the server to protect user privacy and prevent data manipulation.

GTM 在用户浏览器中运行，执行的逻辑对用户可见且可被操控。Identity 解析和 token 验证必须保留在服务端，以保护用户隐私并防止数据被篡改。
