PRD-PLS-001 · Pulse Module

Pulse → V2
信号提取规范Signal Extraction Specification

定义 Pulse 需要提取、聚合并交付给 V2 的信号规范，以支持 tag 生成和 Audience Gallery 用户画像。 Defines what Pulse must extract, aggregate, and deliver to enable V2 tag generation and Audience Gallery profiling. Defines what Pulse must extract, aggregate, and deliver to V2.

01

背景 BackgroundBackground

中文
Audience Gallery 最终需要分析的是 user-level insight，而 Pulse 当前可以从 WhatsApp / Telegram 群中获取到大量消息内容、群活动信息和 member 标识。

为了让这些数据被 Gallery 和 v2 tag system 使用，Pulse 需要提取可复用的用户行为信号（signals）并以结构化格式输出。V2 再统一完成 identity mapping、tag 生成和 Gallery 展示。
English
Audience Gallery requires user-level insight to power segmentation, MA triggers, and audience activation. Pulse currently collects message content, group activity, and member identifiers from WhatsApp and Telegram groups at scale.

To make this data usable by Gallery and the v2 tag system, Pulse must extract reusable member-level behavioral signals and deliver them in a structured format. V2 then handles identity mapping, tag generation, and Gallery display.
核心原则：Pulse 负责观察和聚合，V2 负责解释和打标，两者职责必须清晰分离。 Key principle: Pulse observes and aggregates. V2 interprets and tags. These responsibilities must stay clearly separated.
02

目标 ObjectiveObjective

本需求目标不是让 Pulse 产出 tag，而是让 Pulse 提供以下三类产出。 The goal is not for Pulse to generate tags. Pulse delivers three core outputs.
#产出Output说明Description
1member 维度聚合信号Member-level aggregated signals每个滚动窗口的活跃度和关键词命中次数Activity counts and keyword mention counts per rolling window
2外部身份信息External identity information可映射到 V2 用户的外部身份标识Stable identifiers mappable to V2 user profiles
3低成本结构化输出Low-cost structured output不将 raw message 同步至 BQ，保持低运营成本No raw message sync to BigQuery — keeps operational cost low

04

Member 标识设计 Member Identity DesignMember Identity Design

Pulse 没有独立 user id，member 标识来源不统一。本阶段不要求 Pulse 解决跨平台合并，只需输出当前可获取的外部标识，V2 做后续 mapping。 Pulse has no unified user ID. Member identifiers vary across platforms. Pulse only needs to output available external identifiers — V2 handles downstream mapping.

如存在 normalized_phone，则 phone 优先作为最强 identity signal。如没有 phone，则保留 lid / telegram_id 供 V2 后续 mapping 使用。Phase 1 不要求跨平台合并。 If normalized_phone is available, treat it as the strongest identity signal. If not, preserve lid or telegram_id for V2 downstream mapping. Cross-platform merging is not required in Phase 1.

6.2 信号字段 — mention_count 口径说明 Signal Fields & De-dup Rule6.2 Signal Fields — mention_count Convention
去重口径（关键）：mention_count 以消息为粒度去重。同一条消息命中同一 category 的多个关键词，只算 1 次 mention，不是 N 次。 De-duplication rule (critical): mention_count is de-duplicated at the message level. One message matching multiple keywords in the same category = 1 mention, not N.
Phase 1 约定：mention_count_30d = N 等价于该 category 的 N 次 signal_count，1:1 映射，不做 confidence 计算。V2 直接以此触发 tag rule 判断。 Phase 1 mapping: mention_count_30d = N → V2 treats this as N signal hits. 1:1 mapping, no confidence calculation applied.
