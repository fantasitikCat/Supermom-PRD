Event ID Uniqueness & Dual-Track Architecture

Documents the root cause of duplicate event_id in BigQuery, compares two architectural options, and records the adopted solution. 记录 BigQuery 中 event_id 重复的根本原因、两种架构方案的对比，以及最终采用的解决方案。
DocDECISION-TRK-001
StatusAdopted 已采纳
AffectsFrontend · GTM · BigQuery
§1

Root cause 根本原因

The problem originates from having two sources pushing e-commerce events into the dataLayer at the same time — the frontend pushing directly, and GTM converting from custom events.

How the conflict happens

The e-commerce event model (GA4 Enhanced Ecommerce) is designed to push multiple items in one batch. The custom event model pushes one item at a time. When both run simultaneously, the same user action generates multiple records with conflicting or missing event_id values.

── Frontend pushes (custom events — one per card) ──────────────────
dataLayer.push({ event: "content_impression", event_id: "evt_001", content_id: "cmp_001" });
dataLayer.push({ event: "content_impression", event_id: "evt_002", content_id: "cmp_002" });
dataLayer.push({ event: "content_impression", event_id: "evt_003", content_id: "cmp_003" });

── Frontend ALSO pushes (e-commerce — batch, no event_id) ──────────
dataLayer.push({
  event: "view_item_list",   // ← no event_id
  ecommerce: {
    items: [
      { item_id: "cmp_001", index: 1 },
      { item_id: "cmp_002", index: 2 },
      { item_id: "cmp_003", index: 3 }  // ← 3 items, 1 event
    ]
  }
});
Two sources, two different shapes. Custom events are 1-to-1 (one push per card, with event_id). E-commerce events are 1-to-N (one push for all visible cards, no event_id). They cannot be joined in BigQuery.两种来源，两种数据形态。自定义事件是一卡一推（有 event_id），电商事件是一次批量推送（无 event_id）。两者在 BQ 里无法 join。
§2

With both sources active, BigQuery receives conflicting data for the same user action:

Three consequences:

1. event_id is NULL on all view_item_list rows — impossible to join with content_impression.
2. 3 items share 1 event — the batch push cannot be split into individual records without data transformation.
3. Double counting — the same impression is counted once in content_impression and once inside the batch view_item_list.1. view_item_list 的 event_id 全为 NULL，无法与 content_impression join。2. 3 个内容共享 1 个事件，批量 push 无法拆分成独立记录。3. 同一次曝光被计算两次。
§3

Option A — Frontend pushes both tracks 方案 A：前端直接推送两套

Frontend continues to push both content_impression (custom) and view_item_list (e-commerce) directly. GTM consumes both.

// Frontend pushes BOTH for the same card
dataLayer.push({ event: "content_impression", event_id: "evt_001", content_id: "cmp_001" });
dataLayer.push({ event: "view_item_list", ecommerce: { items: [{ item_id: "cmp_001" }] } });
// ↑ No event_id — cannot be linked to content_impression in BQ
✗ Disadvantages
  • event_id missing from e-commerce events — BQ join impossible
  • Frontend must maintain two separate push logics for every component
  • Every new page or component requires updating both tracks
  • QA must test two separate event streams
  • Filter state must be duplicated into e-commerce item fields manually
  • High maintenance cost — two sources can drift out of sync silently
✓ Advantages
  • E-commerce events visible directly in dataLayer for debugging
  • No GTM dependency for e-commerce data
§4

Option B — GTM as the only conversion layer 方案 B：GTM 作为唯一转换层

Frontend pushes only custom events (content_impression, content_click, content_view). GTM reads each event and generates the corresponding GA4 e-commerce event, carrying the same event_id.

── Frontend pushes (custom events only) ────────────────────────────
dataLayer.push({ event: "content_impression", event_id: "evt_001", content_id: "cmp_001" });

── GTM converts automatically ───────────────────────────────────────
// GTM Tag reads event_id from dataLayer and fires:
gtag('event', 'view_item_list', {
  event_id: "evt_001",  // ← same event_id as content_impression
  items: [{ item_id: "cmp_001" }]
});
✓ Advantages
  • event_id is identical in both events — BQ join works perfectly
  • Frontend writes one push per card — no duplication of logic
  • New pages only need to implement the custom event — e-commerce follows automatically
  • Filter state flows from custom event to e-commerce automatically via GTM mapping
  • Single source of truth — only one event stream to QA and maintain
  • GTM field mapping is the single place to update if GA4 e-commerce schema changes
✗ Disadvantages
  • E-commerce events depend on GTM being correctly configured
  • GTM Preview required to verify e-commerce output

§6

Adopted solution 采纳方案

Decision 决策
Option B — GTM as the only e-commerce conversion layer
Frontend pushes custom events only. GTM converts content_impression → view_item_list, content_click → select_item, content_view → view_item. The same event_id is carried from the frontend push into the GTM-generated e-commerce event, guaranteeing uniqueness in BigQuery. 前端只推送自定义事件。GTM 负责转换三个电商事件。event_id 从前端 push 透传到 GTM 生成的电商事件，保证 BigQuery 中的唯一性。

§7

Required actions 必须执行的操作

01
Frontend: remove direct push of view_item_list
Any existing code that pushes view_item_list directly to the dataLayer must be removed. GTM will generate this event automatically from content_impression.
02
Frontend: remove direct push of select_item
Any existing code that pushes select_item directly must be removed. GTM will generate it from content_click.
03
Frontend: remove direct push of view_item
Any existing code that pushes view_item directly must be removed. GTM will generate it from content_view.
04
Frontend: generate event_id on every dataLayer.push
Use crypto.randomUUID(). Generate once per push — do NOT reuse across events. See IMPL-TRK-001 §1 for the helper function.
05
GTM: configure conversion Tags for the three e-commerce events
Configure GA4 - view_item_list, GA4 - select_item, GA4 - view_item Tags as documented in IMPL-TRK-GTM-001 §4–§6. Each Tag must read {{DLV - event_id}} and include it in the GA4 event payload.
06
GTM: verify event_id flows through in Preview
In GTM Preview, confirm that the event_id value in the fired view_item_list Tag matches the event_id in the triggering content_impression dataLayer entry.
§8

Migration sequence 迁移顺序

Do NOT delete frontend code and configure GTM at the same time. Complete GTM setup and verify first, then remove frontend pushes. This ensures GA4 report data has zero interruption.不要同时删除前端代码和配置 GTM。先完成 GTM 配置并验证，再删除前端 push，确保 GA4 报表数据零中断。
01
Configure GTM conversion Tags
Set up GA4 - view_item_list, GA4 - select_item, GA4 - view_item Tags in GTM as documented in IMPL-TRK-GTM-001 §4–§6. Do NOT publish yet.
02
Verify in GTM Preview
Use GTM Preview mode to confirm: (a) each Tag fires on the correct trigger event, (b) event_id in the fired Tag matches the event_id in the triggering dataLayer entry, (c) field mapping is correct.
03
Publish GTM
Publish the GTM container. At this point both the GTM-generated e-commerce events AND the frontend-pushed e-commerce events are active simultaneously. This is temporary and expected.
04
Verify GA4 real-time report
In GA4 → Reports → Realtime, confirm view_item_list, select_item, view_item are appearing. Check that the Purchase Journey funnel shows data in all stages.
05
Frontend removes three direct pushes
Remove all frontend code that directly pushes view_item_list, select_item, view_item. Deploy the frontend change.
06
Final verification
After frontend deploy: (a) confirm GA4 e-commerce events are still appearing (now only from GTM), (b) confirm BQ event_id is no longer NULL on e-commerce events, (c) confirm no duplicate rows per event_id.
§9

Expected BigQuery result 预期 BQ 结果

After the solution is implemented, every event_id appears exactly twice — once for the custom event and once for the e-commerce event. This enables a precise 1:1 join.

event_ideventcontent_id
evt_001content_impressioncmp_001
evt_001view_item_listcmp_001
evt_002content_impressioncmp_002
evt_002view_item_listcmp_002
evt_003content_clickcmp_001
evt_003select_itemcmp_001
BQ join query: 
SELECT ci.content_id, ci.filter_audience, ci.impression_position,
       vil.item_list_name
FROM events ci
JOIN events vil ON ci.event_id = vil.event_id
WHERE ci.event = 'content_impression'
  AND vil.event = 'view_item_list'
