§02

Variables 变量配置

Variables read values from the page, dataLayer, or cookies and make them available to Tags. The following variables are required for the v3 tracking system. 变量从页面、dataLayer 或 Cookie 中读取值，供 Tag 使用。以下变量是 v3 追踪系统的必配变量。

Group A — Identity variables 身份变量

These variables resolve anonymous_id and session_id from GA4's native cookies. They must be configured before any GA4 event tag is created. 这两个变量从 GA4 的原生 Cookie 读取匿名 ID 和会话 ID，必须在创建任何 GA4 事件 Tag 之前完成配置。

JS - GA4 Client ID JavaScript Variable
Purpose 用途Reads GA4's client_id from the _ga cookie. This becomes anonymous_id.从 _ga Cookie 读取 GA4 的 client_id，作为 anonymous_id 使用。
Variable typeCustom JavaScript
CodeSee code block below
// JS - GA4 Client ID
// Reads the _ga cookie and extracts the client_id portion
function() {
  var cookie = {};
  document.cookie.split(';').forEach(function(c) {
    var parts = c.trim().split('=');
    cookie[parts[0]] = parts.slice(1).join('=');
  });
  var ga = cookie['_ga'];
  if (!ga) return '';
  // _ga format: GA1.2.XXXXXXXXXX.XXXXXXXXXX → extract last two segments
  var parts = ga.split('.');
  return parts.slice(2).join('.');
}
JS - GA4 Session ID JavaScript Variable
Purpose 用途Reads GA4's ga_session_id from the measurement ID cookie. This becomes session_id.从 GA4 测量 ID 对应的 Cookie 中读取 ga_session_id，作为 session_id 使用。
Variable typeCustom JavaScript
Important 注意Replace G-XXXXXXXX with the actual GA4 Measurement ID before deploying.部署前替换为实际的 GA4 测量 ID。
// JS - GA4 Session ID
// Reads _ga_XXXXXXXX cookie and extracts ga_session_id
function() {
  var measurementId = 'G-XXXXXXXX'; // ← replace with actual Measurement ID
  var cookieName = '_ga_' + measurementId.replace('G-', '');
  var cookie = {};
  document.cookie.split(';').forEach(function(c) {
    var parts = c.trim().split('=');
    cookie[parts[0]] = parts.slice(1).join('=');
  });
  var val = cookie[cookieName];
  if (!val) return '';
  // Cookie format: GS1.1.SESSION_ID.1.1.TIMESTAMP.0.0.0
  var parts = val.split('.');
  return parts[2] || '';
}

Triggers 触发器配置

Triggers determine when a Tag fires. The following triggers are required for the v3 system. 触发器决定 Tag 何时触发。以下触发器是 v3 系统的必配触发器。

T-01 — History Change (SPA page_view) SPA 页面浏览触发器

React SPA navigation does not trigger a full browser reload. This trigger fires on every URL change inside the app, enabling GTM to detect page navigation. React SPA 页面跳转不会触发浏览器完整重载。此触发器在应用内每次 URL 变更时触发，使 GTM 能够检测到页面导航。

HistoryChange - SPA Navigation History Change Trigger
Trigger typeHistory Change
Fire onAll History Changes
Why 原因Captures every React Router navigation event, including pushState and replaceState.捕获所有 React Router 导航事件，包括 pushState 和 replaceState。
Important / 注意： The History Change trigger fires before the new page's dataLayer push. Tags using this trigger will read the previous page's dataLayer values. Always use the CE - page_view Custom Event trigger (below) for page_view events instead. History Change 触发器在新页面的 dataLayer push 之前触发。使用此触发器的 Tag 会读取上一页的 dataLayer 值。page_view 事件请使用下方的 CE - page_view 自定义事件触发器。

CH — Impression Observer 内容曝光观察器

This Custom HTML Tag implements content_impression tracking using the browser's native IntersectionObserver API. It observes all DOM elements with a data-track-impression attribute and fires a dataLayer push when the element has been at least 50% visible for at least 1 second. 此自定义 HTML 标签使用浏览器原生 IntersectionObserver API 实现 content_impression 追踪。它监听所有带有 data-track-impression 属性的 DOM 元素，当元素可见 ≥ 50% 且持续 ≥ 1 秒时，触发 dataLayer push。

Frontend requirement / 前端要求： Every trackable content card must have a data-track-impression attribute containing a JSON-stringified payload with the fields listed below. The GTM tag reads this attribute — it does not guess field values. 每个需要追踪曝光的内容卡片必须带有 data-track-impression 属性，值为 JSON 字符串，包含以下字段。GTM 标签读取此属性，不自动猜测字段值。

Required HTML attribute format 前端必须提供的属性格式

<!-- Example content card markup / 内容卡片示例 -->
<div
  class="content-card"
  data-track-impression='{
    "content_id": "article_123",
    "content_type": "article",
    "content_format": "mixed",
    "content_category": "pregnancy_birth",
    "component_type": "recommendation_widget",
    "impression_position": 2
  }'
>
  ...card content...
</div>

Custom HTML Tag code — CH - Impression Observer

// CH - Impression Observer
// Fires content_impression when element is ≥50% visible for ≥1s
// Requires: data-track-impression attribute on content card elements

<script>
(function() {
  // Prevent duplicate initialisation on SPA navigation
  if (window.__impressionObserverActive) return;
  window.__impressionObserverActive = true;

  var timers = new Map();
  var fired = new Set();

  var observer = new IntersectionObserver(function(entries) {
    entries.forEach(function(entry) {
      var el = entry.target;
      var key = el.dataset.impressionKey;

      if (entry.isIntersecting && entry.intersectionRatio >= 0.5) {
        // Element entered viewport at ≥50% — start 1s timer
        if (!timers.has(key) && !fired.has(key)) {
          var timer = setTimeout(function() {
            if (fired.has(key)) return;
            fired.add(key);
            timers.delete(key);

            var payload = {};
            try {
              payload = JSON.parse(el.getAttribute('data-track-impression'));
            } catch(e) {
              console.warn('[Impression Observer] Invalid JSON on element', el);
              return;
            }

            window.dataLayer = window.dataLayer || [];
            window.dataLayer.push({
              event: 'content_impression',
              content_id:       payload.content_id       || null,
              content_type:     payload.content_type     || null,
              content_format:   payload.content_format   || null,
              content_category: payload.content_category || null,
              component_type:   payload.component_type   || null,
              impression_position: payload.impression_position || null
            });
          }, 1000); // 1000ms = 1 second threshold
          timers.set(key, timer);
        }
      } else {
        // Element left viewport — cancel timer
        if (timers.has(key)) {
          clearTimeout(timers.get(key));
          timers.delete(key);
        }
      }
    });
  }, { threshold: 0.5 }); // Trigger at 50% visibility

  function observeElements() {
    var elements = document.querySelectorAll('[data-track-impression]');
    elements.forEach(function(el, index) {
      // Assign a unique key per element for deduplication
      if (!el.dataset.impressionKey) {
        el.dataset.impressionKey = 'imp_' + Date.now() + '_' + index;
      }
      observer.observe(el);
    });
  }

  // Initial observation on page load
  observeElements();

  // Re-observe after SPA navigation — listen for page_view events
  window.dataLayer = window.dataLayer || [];
  var originalPush = window.dataLayer.push.bind(window.dataLayer);
  window.dataLayer.push = function(obj) {
    originalPush(obj);
    if (obj && obj.event === 'page_view') {
      // Reset fired set on page navigation; re-observe new content
      fired.clear();
      timers.forEach(function(t) { clearTimeout(t); });
      timers.clear();
      window.__impressionObserverActive = false;
      setTimeout(observeElements, 300); // Wait for React to render new content
    }
  };
})();
</script>

CH — Chat Duration 聊天时长计算

This Custom HTML Tag calculates the chat_duration_sec field when the AIMA chat window is closed. It reads the chat_open_time timestamp set by a companion snippet on chat_open, and computes the elapsed time in seconds. 此标签在 AIMA 聊天窗口关闭时计算 chat_duration_sec 字段。它读取 chat_open 时记录的 chat_open_time 时间戳，计算经过的秒数。

Two-tag pattern / 双标签模式： This requires two Tags — one fires on chat_open to record the start time, one fires on chat_close to calculate and inject duration. 此功能需要两个标签配合：一个在 chat_open 时记录开始时间，一个在 chat_close 时计算并注入时长。

Tag 1 of 2 — Record open time (fires on CE - chat_open)

// CH - Chat Open Timer
// Fires on: CE - chat_open
// Records the timestamp when chat window opens

<script>
  window.__chatOpenTime = Date.now();
</script>

Tag 2 of 2 — Calculate duration and inject (fires on CE - chat_close)

// CH - Chat Duration
// Fires on: CE - chat_close
// Calculates chat_duration_sec and re-pushes to dataLayer

<script>
(function() {
  var openTime = window.__chatOpenTime;
  if (!openTime) return; // No open time recorded — skip

  var durationMs  = Date.now() - openTime;
  var durationSec = Math.round(durationMs / 1000);

  window.__chatOpenTime = null; // Reset for next session

  // Inject chat_duration_sec into the dataLayer event
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push({
    chat_duration_sec: durationSec
  });
})();
</script>

CH — ID Injection 身份 ID 注入

This Custom HTML Tag reads anonymous_id and session_id from the GA4 cookies and writes them explicitly into window.dataLayer. This ensures that all subsequent event pushes have access to these values even before the GA4 library has fully initialised. 此标签从 GA4 Cookie 读取 anonymous_id 和 session_id，并显式写入 dataLayer。确保所有后续事件 push 都能使用这两个值，即使在 GA4 库完全初始化之前。

Trigger / 触发器： AllPages - On Load. Must fire before any GA4 event tag. Set Tag sequencing in GTM if needed. 触发器：所有页面加载。必须在任何 GA4 事件标签之前触发。如有需要，在 GTM 中设置 Tag 顺序。 
// CH - ID Injection
// Fires on: AllPages - On Load (must fire before GA4 event tags)
// Writes anonymous_id and session_id into dataLayer

<script>
(function() {
  function getCookieValue(name) {
    var match = document.cookie.match(new RegExp('(^| )' + name + '=([^;]+)'));
    return match ? match[2] : null;
  }

  // Read GA4 client_id from _ga cookie
  var ga = getCookieValue('_ga');
  var anonymousId = null;
  if (ga) {
    var parts = ga.split('.');
    anonymousId = parts.slice(2).join('.');
  }

  // Read ga_session_id from _ga_MEASUREMENTID cookie
  var measurementId = 'G-XXXXXXXX'; // ← replace with actual Measurement ID
  var sessionCookieName = '_ga_' + measurementId.replace('G-', '');
  var sessionCookie = getCookieValue(sessionCookieName);
  var sessionId = null;
  if (sessionCookie) {
    var sParts = sessionCookie.split('.');
    sessionId = sParts[2] || null;
  }

  // Write to dataLayer
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push({
    anonymous_id: anonymousId,
    session_id:   sessionId
  });
})();
</script>

DebugView guide DebugView 调试指南

DebugView in GA4 shows real-time events from your browser session. Use it to validate that events are arriving correctly before publishing a GTM version. GA4 的 DebugView 实时显示来自你浏览器的事件。在发布 GTM 版本前，使用它验证事件是否正确到达。

01
Enable GTM Preview mode 启用 GTM 预览模式
In GTM, click Preview. Enter the URL of the site to debug. GTM will open the site with the preview container active.在 GTM 中点击 Preview，输入需要调试的站点 URL，GTM 会以预览容器打开该站点。
02
Open GA4 DebugView 打开 GA4 DebugView
In GA4, go to Admin → DebugView. Your device should appear automatically once the preview session is active.在 GA4 中进入 Admin → DebugView，预览会话激活后你的设备会自动出现。
03
Verify event parameters 验证事件参数
Click any event in DebugView to expand it. Verify that all required fields are present, non-null, and contain valid enum values per the Tracking Dictionary.点击 DebugView 中的任意事件展开查看，验证所有必填字段存在、非空，且枚举值符合《Tracking Dictionary》。
04
Check for duplicate events 检查重复事件
Perform each user action once and count events in DebugView. page_view must appear exactly once per navigation. content_impression must appear once per card per page view.每个用户操作执行一次，在 DebugView 中计数事件。page_view 每次导航只能出现一次，content_impression 每张卡片每次页面浏览只能出现一次。
05
Publish only after all CRITICAL items pass 所有 CRITICAL 项通过后再发布
Return to the QA checklist. All CRITICAL items must be checked before clicking Publish in GTM. Add a version description with the date and list of changes.返回 QA 清单，所有 CRITICAL 项全部通过后，再在 GTM 中点击发布。发布时填写版本说明，包含日期和变更列表。
Version description format / 版本说明格式：
YYYY-MM-DD | [Change summary] | Verified by [name]
例：2025-05-20 | Added form_submit tag for campaign pages | Verified by [engineer name]
