Scope & rules 范围与通用规则

本文档为快速实施参考，字段定义和枚举值以正式文档为准：
· 字段完整定义、条件必填规则 → PRD-TRK-002 Contract v2.0 §02–§04
· 所有枚举值（page_type / content_type / button_action_type 等）→ PRD-TRK-003 Dictionary v2.0
· 本文档中的字段表和示例如与上述文档冲突，以 002 和 003 为准。
Global envelope（全局字段） — page_type session_id anonymous_id v2_uid utm_source utm_medium utm_campaign 必须出现在每一个事件上。见 Contract §02。下方每个事件的字段表和示例已省略这些字段，以保持简洁。
Owner 说明： Frontend = 前端自行产生并填写 · Backend = 后端逻辑产生，前端从页面数据/props 中读取 · API pass-through = 直接透传 API 响应字段，不做修改
追踪边界： 用户点击 "Join on WhatsApp / Telegram" 后离开 Supermom，追踪即告结束。原生 WhatsApp / Telegram 的加入确认行为不在追踪范围内，不得尝试追踪。

recommendation_sourceYES登录状态决定："rule_based"（已登录）· "default"（未登录）前端根据登录状态判断，无需从 API 读取。见 Dictionary §5Frontend

Flashcard detail page 闪卡详情页 /question/:id

page_type: "detail" · content_type: "flashcard"

页面流程 F1 page_view
顶部 — 答题区 F2 submit_answer
中部 — 投票区（需滚动） F3 poll impression → F4 submit_vote
底部 — 推荐闪卡 F5 impression → F6 click
答题和投票均属于闪卡内容的组成部分，不是独立内容实体，两者都使用父级闪卡的 content_id。两者均使用 button_click 而非 form_submit——因为这是内容互动，不是业务转化，不进转化漏斗。详见 Contract §09。

F2 · button_click · submit_answer用户提交答题（顶部答题区）INTERACT
触发用户选择答案并点击确认/提交按钮时触发。单选和多选题使用同一事件，无需区分题型。
为什么不用 form_submit？ form_submit 专用于有后端确认的业务转化表单（lead_gen / survey 等活动）。答题是内容互动，提交后用户停留在同一页面，无后端确认回调，不进转化漏斗。见 Contract §09。

Field 字段RequiredValue / sourceOwner
eventYES"content_impression"Frontend
page_typeYES"detail"Frontend

recommendation_sourceYES登录状态决定："rule_based"（已登录，按孩子年龄匹配）· "default"（未登录，展示第一个 filter 的默认结果）前端根据登录状态判断，无需从 API 读取。见 Dictionary §5Frontend

两种登录状态都会展示此 section，但来源不同：
· 已登录：后端根据孩子年龄个性化匹配推荐闪卡 → recommendation_source: "rule_based"
· 未登录：展示第一个 filter 的默认闪卡列表 → recommendation_source: "default"
前端根据登录状态判断，写死对应值，不从 API 读取。
// content_id 是被推荐的闪卡 ID，不是当前页面的 flashcard_id

  page_type: "detail",

  content_type: "flashcard",
  content_id: "<recommended_flashcard_id>",
  recommendation_source: isLoggedIn ? "rule_based" : "default",
  impression_position: 1
});
