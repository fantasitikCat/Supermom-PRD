Purpose and background 目的与背景

This document defines the standardized event tracking specification for the Supermom platform. It establishes a unified data collection framework to ensure consistent, accurate, and auditable measurement of user interactions across all platform versions and surfaces. 本文档定义 Supermom 平台的标准化事件追踪规范，建立统一的数据采集框架，确保跨版本、跨端的用户行为数据具备一致性、准确性与可审计性。

The need for this specification arises from the following identified conditions: 制定本规范的背景来自以下已识别的现状问题：

Condition 背景条件Detail 说明
Platform migration in progress
平台版本迁移进行中		 The platform is undergoing a structured migration from version 2 (supermom.com) to version 3 (v3.supermom.com), during which both versions operate concurrently.平台正从 v2 向 v3 进行结构性迁移，迁移期间两个版本并行运行。
No unified event naming convention
缺乏统一事件命名规范		 Prior to this specification, no formally approved event naming convention existed across teams or systems.本规范制定前，各团队和系统之间不存在经正式批准的事件命名规范。
Inconsistent parameter implementation
参数传递不一致		 Event parameters were implemented inconsistently across user interaction types, resulting in unreliable behavioral data.各交互类型的事件参数传递方式不统一，导致行为数据不可靠。
User identity continuity not maintained
用户身份连续性未被系统维护		 User identity continuity across sessions and anonymous states was not systematically maintained.用户跨 session 和匿名状态的身份连续性未被系统性地维护。
No single source of truth
缺乏唯一权威文档		 No formally approved reference document existed to govern tracking implementation decisions.此前不存在经正式批准的参考文档来规范追踪实施决策。
This specification serves as the single source of truth for all tracking-related implementation, validation, and governance activities. 本规范是所有追踪相关的实施、验收和治理活动的唯一权威来源。

Core design principle 核心设计原则

This tracking system has one responsibility: collect raw data and store it accurately. Calculation, aggregation, and presentation are handled by downstream systems. This boundary is intentional and must not be blurred. 本追踪系统只有一个职责：采集原始数据并准确存储。计算、聚合和展示由下游系统负责。这条边界是有意为之的，不得模糊。

💡
"What happened?" — not "What does it mean?" 「发生了什么」而非「这意味着什么」
This system answers the first question only. A raw form_submit event tells you a form was submitted. Whether that submission counts as a "conversion" — and how that conversion is defined, attributed, and reported — is a downstream concern. 本系统只回答第一个问题。原始的 form_submit 事件告诉你表单被提交了。这次提交是否算作"转化"、如何定义、如何归因、如何展示，属于下游系统的职责。
ISO reference — Separation of Concerns / ISO 参考原则：关注点分离
This principle is consistent with ISO/IEC 25010 quality characteristic Functional Suitability — each system component fulfils its defined function and does not encroach on adjacent layers. Changes to computation logic or dashboard design do not require changes to this specification. 本原则符合 ISO/IEC 25010 质量特性中的「功能适合性」——每个系统组件完成其定义的功能，不侵入相邻层。计算逻辑或看板设计的变更，不需要修改本规范。
03

Two tracking tracks 两套并行的追踪体系

The system runs two parallel tracks. They do not conflict — they serve different purposes and are joined in BigQuery via v2_uid. 系统同时运行两套追踪体系，两者不冲突——目的不同，在 BigQuery 中通过 v2_uid 关联。

Track A — Frontend Tracking（前端追踪）
行为分析体系 · 本文档体系
Records what users do on each page and component记录用户在每个页面和组件上的行为
Uses dataLayer.push → GTM → GA4 → BigQuery通过 dataLayer → GTM → GA4 → BigQuery 流转
Session-level attribution with utm_* parameters用 utm_* 做 session 级归因，每次新 session 可覆盖
Owner: Frontend + GTM
Defined in → Tracking Master PRD
Track B — Backend Attribution（后端归因）
来源归因体系 · acq_* 体系
Records where users came from when they first enter记录用户首次进入时的来源（First-touch）
Writes acq_* fields to backend database将 acq_* 字段写入后端数据库，不经过 dataLayer
First-touch only — never overwritten只记录一次，不覆盖
Owner: Backend
Defined in → Landing Page Attribution PRD + acq_* 字段说明
Critical boundary / 关键边界： acq_* fields must NEVER appear in dataLayer.push. They are backend-only. acq_* 字段严禁出现在 dataLayer.push 中，这是后端专用字段。前端 tracking 使用 utm_* 参数，两者通过 v2_uid 在 BigQuery 关联。

Team ownership 团队职责分工

Every field in the tracking system has a single owner. When data is missing in production, this table determines who is responsible. 追踪系统中每个字段都有唯一负责人。线上数据缺失时，按此表确认责任方。

Frontend
Triggers dataLayer.push at the right time with the right fields. Implements UI-layer tracking including impressions, scroll depth, and button clicks.在正确时机触发 dataLayer.push，实现曝光、滚动深度、按钮点击等 UI 层追踪。
event · page_type · component_type · source_component · impression_position · clicked_position · button_action_type · target_type · chat_duration_sec · video_percent
Backend
Provides content metadata in API responses for frontend to use in dataLayer. Also owns the acq_* attribution system.在 API 响应中提供内容元数据供前端写入 dataLayer。同时负责 acq_* 归因体系。
content_id · content_type · campaign_id · campaign_type · form_id · source_campaign_id · video_id · video_duration_sec · v2_uid · profile_id
CMS
Assigns content classification at publish time. Must never leave content_category as uncategorized in production.在内容发布时设置内容分类。生产环境中 content_category 不得为 uncategorized。
content_category · content_topic · content_format
GTM
Reads dataLayer, forwards events to GA4. Reads GA4 client_id and ga_session_id and writes them back as anonymous_id and session_id. Manages UTM persistence.读取 dataLayer，转发事件到 GA4。读取 GA4 client_id 并写回为 anonymous_id。管理 UTM 持久化。
anonymous_id · session_id · utm_source · utm_medium · utm_campaign · site_version
AI / Search
Classifies raw user input into topic labels. Raw messages must never be sent as tracking parameters.将用户原始输入分类为主题标签。原始消息内容严禁作为追踪参数传入。
question_topic · search_topic
Backend (acq_*)
Writes acq_* fields to the backend database when user first enters a Landing Page. This is separate from the dataLayer tracking system.用户首次进入 Landing Page 时将 acq_* 写入后端数据库。与 dataLayer 追踪体系完全独立。
acq_platform · acq_channel · acq_source · acq_referrer · acq_campaign_id · acq_group_id

Key rules 关键约定 — 最容易出错的5条规则

These 5 rules prevent the most common mistakes. Every developer must know them.这 5 条规则防止最常见的错误。每个开发者都必须知道。

01
One event name per action type 同类行为只有一个事件名
Never create banner_click or campaign_click. Use content_click with component_type: "banner" to distinguish context.禁止创建 banner_click 或 campaign_click。统一用 content_click，通过 component_type 区分业务场景。
02
acq_* fields never go in dataLayer acq_* 字段严禁进入 dataLayer
acq_channel, acq_source, acq_referrer are backend-only. Frontend uses utm_source / utm_medium. AIMA is utm_source: "aima" — never "aima_bot".acq_* 是后端字段，前端使用 utm_* 参数。AIMA 在前端统一写 utm_source: "aima"，不是 "aima_bot"。
03
form_submit fires only after backend confirms form_submit 只在后端确认后触发
Do not fire form_submit when the user clicks the submit button. Fire it only after the backend API returns success. Otherwise conversion data will be inflated.不要在用户点击提交按钮时触发，只在后端 API 返回成功后触发。否则转化数据会虚高。
04
Never send raw user input as tracking parameters 严禁将用户原始输入作为追踪参数
search_topic and question_topic must be AI-classified topic labels. Raw search queries and raw chat messages must never appear in any tracking payload.search_topic 和 question_topic 必须是 AI 分类后的标签，不是用户原始输入。原始搜索词和聊天内容严禁出现在任何 tracking payload 中。
05
anonymous_id and session_id come from GTM, not frontend code anonymous_id 和 session_id 由 GTM 写入，不是前端自行生成
GTM reads GA4's client_id and ga_session_id and writes them explicitly into dataLayer as anonymous_id and session_id. Frontend code must not generate these independently.GTM 读取 GA4 的 client_id 和 ga_session_id，写入 dataLayer。前端不要自行生成这两个字段，否则会出现多套 session 不一致的问题。

Glossary 术语表

dataLayer A JavaScript array on the page that frontend code pushes events into. GTM listens to it.页面上的 JavaScript 数组，前端代码将事件推送到这里，GTM 监听并读取。
event A named user action (e.g. content_click, form_submit). The unit of tracking.一个命名的用户行为（如 content_click、form_submit）。追踪的基本单位。
anonymous_id Browser-level identifier. Sourced from GA4's client_id. Persists across sessions until cookie is cleared.浏览器级别的用户标识符，来自 GA4 的 client_id，跨 session 持续存在直到 cookie 被清除。
session_id Session-level identifier. Sourced from GA4's ga_session_id. Resets after 30 minutes of inactivity.会话级别的标识符，来自 GA4 的 ga_session_id，30 分钟无操作后重置。
v2_uid Authenticated user ID. Set by backend after OTP verification. Links anonymous behaviour to a known user.认证用户 ID，OTP 验证成功后由后端设置，将匿名行为与已知用户关联。
content_type What the content entity is: article, campaign, qa, group, external_link.内容实体的类型：文章、活动、QA、社群、外部链接。
content_format How the content is presented: article, video, mixed, interactive. Separate from content_type.内容的呈现形式：图文、视频、图文+视频、互动。与 content_type 是不同维度。
component_type The UI component the user interacted with (e.g. banner, recommendation_widget). Not the same as content_type.用户交互的 UI 组件（如 banner、recommendation_widget），与 content_type 不同。
First-touch attribution首次触达归因 The acq_* system records only the first source when a user enters. It never gets overwritten.acq_* 体系只记录用户首次进入时的来源，后续访问不覆盖。
Last non-direct click末次非直接点击归因 The utm_* attribution model used in GA4. The most recent non-direct source gets credit for a conversion.GA4 中使用的 utm_* 归因模型，最近一次非直接来源获得转化归因。
site_version A GTM-injected field that identifies which version of the site the event came from: "v2" or "v3".GTM 自动注入的字段，标识事件来自哪个版本的网站：v2 或 v3。
SPA (Single Page Application)单页应用 React apps where page navigation does not cause a full browser reload. Requires History Change Trigger in GTM for page_view tracking.React 应用的页面跳转不会触发完整的浏览器重载，GTM 需要用 History Change Trigger 来触发 page_view。
