§01

Purpose and background 目的与背景

The acq_* field system establishes a unified user acquisition attribution framework across all platforms and channels. It resolves the following identified problems in the prior system. acq_* 字段体系建立统一的用户获取归因框架，覆盖所有平台和渠道，解决以下在原有系统中识别的问题。

Problem 问题Resolution 解决方案
Source field semantics were inconsistent across teams各团队的 source 字段语义混乱 Unified acq_* schema with strict enum values统一 acq_* 模型，严格枚举值
Web / App / WhatsApp / AIMA entry points could not be unifiedWeb / App / WhatsApp / AIMA 入口无法统一 acq_platform + acq_channel + acq_source three-layer model平台 + 渠道 + 来源三层模型
OTP and form data were disconnected from acquisition sourceOTP 与表单数据与来源脱节 OTP binding links anonymous_id ↔ uid ↔ acq_*OTP 绑定建立 anonymous_id ↔ uid ↔ acq_* 关联
Full user conversion path could not be reconstructed无法完整还原用户转化路径 First-touch recording + uid linkage enables end-to-end attribution首次触达记录 + uid 关联实现端到端归因
§02

Usage rules 使用规则

These rules govern how all acq_* fields are recorded and maintained. All backend implementations must comply. 以下规则约束所有 acq_* 字段的记录和维护方式，所有后端实施必须遵守。

#Rule 规则Detail 说明
R-01 First-touch only — never overwrite
首次触达，永不覆盖		 acq_* fields are recorded once at the user's first Landing Page entry. Subsequent visits, channel switches, or platform changes must not overwrite the recorded values.acq_* 字段仅在用户首次进入 Landing Page 时记录一次，后续访问、渠道切换或平台变更均不覆盖已记录的值。
R-02 platform and channel are independent
platform 与 channel 相互独立		 acq_platform records which product the user is in. acq_channel records where the user came from. A user can be in the app (platform = supermom_3_0) but arrived via WhatsApp (channel = whatsapp). These do not conflict.platform 记录用户在哪个产品内，channel 记录用户从哪里来。两者独立，不互相影响。
R-03 OTP stage does not re-collect source
OTP 阶段不重新采集来源		 At OTP success, only anonymous_id ↔ uid binding is performed. The acq_* values already recorded from the Landing Page entry are used as-is.OTP 成功时只做 anonymous_id ↔ uid 绑定，使用 Landing Page 已记录的 acq_* 值，不重新采集。
R-04 Form submission does not repeat acq_* fields
表单提交不重复记录 acq_* 字段		 Form conversion is linked to source via uid: form → uid → acq_*. Do not re-record acq_* on the form submission record.表单转化通过 uid 关联来源：form → uid → acq_*。不在表单记录中重复填写 acq_* 字段。
R-05 Default when no source information is present
无来源信息时的默认值		 If no acquisition parameters are present when the user enters, set acq_channel = direct. All other acq_* fields may be left null.用户进入时若无任何来源参数，设置 acq_channel = direct，其他 acq_* 字段可为 null。
R-06 AIMA always belongs to WhatsApp channel
AIMA 始终归属于 WhatsApp 渠道		 acq_channel = whatsapp, acq_source = aima_bot. AIMA is a source subdivision within WhatsApp, not a separate channel.acq_channel = whatsapp，acq_source = aima_bot。AIMA 是 WhatsApp 渠道下的来源细分，不是独立渠道。
R-07 acq_group_id is WhatsApp channel only
acq_group_id 仅适用于 WhatsApp 渠道		 acq_group_id is only populated when acq_channel = whatsapp. It must be null for all other channels.acq_group_id 仅在 acq_channel = whatsapp 时填写，其他渠道必须为 null。
§03

Recording flow 记录流程

The standard user path from external source to form conversion, and what the backend records at each stage. 从外部来源到表单转化的标准用户路径，以及后端在每个阶段记录的内容。

01
External entry point 外部入口
User arrives from WhatsApp / Ads / Website / App / Push notification.用户从 WhatsApp / 广告 / 网站 / App / 推送消息进入。
02
Landing Page entry — record acq_* 进入 Landing Page — 记录 acq_*
Backend records acq_platform, acq_channel, acq_source, acq_referrer, acq_campaign_id, acq_group_id against the user's anonymous_id. This happens only once (First-touch).后端将 acq_* 字段记录到用户的 anonymous_id 下，仅发生一次（首次触达）。
03
User submits OTP 用户提交 OTP
No new acq_* data is collected at this stage.此阶段不采集新的 acq_* 数据。
04
OTP success — identity binding OTP 成功 — 身份绑定
Backend writes to identity_map: links anonymous_id ↔ uid. The existing acq_* recorded in step 02 is now attributable to a known user.后端写入 identity_map：关联 anonymous_id ↔ uid。步骤 02 记录的 acq_* 现在可归因到已知用户。
05
Form submission — conversion record 表单提交 — 转化记录
Backend records uid, form_id, campaign_id, submit_time. Attribution is resolved by joining: form → uid → acq_*. Do not repeat acq_* on the form record.后端记录 uid、form_id、campaign_id、submit_time。通过 form → uid → acq_* 关联归因，不在表单记录中重复填写 acq_*。

§07b

acq_campaign_id & acq_group_id 活动 ID 与群组 ID

acq_campaign_id内部活动 ID Backend

The internal campaign ID associated with the user's entry. Used to link the acquisition record to a specific Supermom campaign.与用户进入关联的内部活动 ID，用于将获取记录关联到具体的 Supermom 活动。

Conditional 条件必填Required when user entry is linked to a specific campaign. Null otherwise.用户进入与特定活动关联时必填，否则为 null。

This is an internal system ID (e.g. a database record ID), not a UTM campaign name. Format is defined by the backend system. 这是内部系统 ID（如数据库记录 ID），不是 UTM campaign 名称。格式由后端系统定义。
acq_group_id群组 ID — 仅适用于 WhatsApp 渠道 Backend

The WhatsApp group ID from which the user was referred. Populated only when acq_channel = whatsapp and the entry originated from a group message.用户被引导进入的 WhatsApp 群 ID，仅在 acq_channel = whatsapp 且来自群消息时填写。

Conditional 条件必填Required when acq_source = whapi_group. Must be null for all other channels.acq_source = whapi_group 时必填，其他所有渠道必须为 null。

Scope restriction / 范围限制： acq_group_id must be null for any entry where acq_channel ≠ whatsapp. Never populate this field for website, app, or ads traffic. acq_channel ≠ whatsapp 的任何进入记录中，acq_group_id 必须为 null。不得为网站、App 或广告流量填写此字段。
§07c · Optional 扩展字段

acq_message_id 消息 ID（可选）

Optional field — not part of the core acq_* model · 可选字段，不属于核心 acq_* 模型
acq_message_id消息级标识符 Optional 可选

Identifies the specific push message that led to the user's entry. Used for message-level analysis, not user-level attribution.标识导致用户进入的具体推送消息，用于消息级分析，不用于用户级归因。

§10

Frontend UTM mapping 前端 UTM 参数对照

acq_* fields are backend-only. The frontend uses utm_* parameters for the same attribution concept. This table maps the two systems for cross-referencing in BigQuery. acq_* 是后端专用字段。前端使用 utm_* 参数表达相同的归因概念。此对照表用于在 BigQuery 中进行跨系统关联分析。

Key rule / 关键规则： AIMA is recorded as acq_source = aima_bot in the backend system, but as utm_source = aima on the frontend. These are the same origin with different naming conventions. They are joined via v2_uid in BigQuery. AIMA 在后端系统中记录为 acq_source = aima_bot，在前端记录为 utm_source = aima。两者是同一来源的不同命名，在 BigQuery 中通过 v2_uid 关联。
