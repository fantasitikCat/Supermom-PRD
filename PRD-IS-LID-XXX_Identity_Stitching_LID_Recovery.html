背景 BackgroundBackground

中文
目前 Pulse 中存在部分 group member，已存在于 Pulse group 中、已产生 message / signal / activity，但由于 WhatsApp 平台限制、用户隐私设置或社群隐私设置，Pulse 无法直接获取这些 member 的手机号。

由此导致：这些 member 无法与 V2 用户完成 identity stitching，进一步影响用户信号聚合、Audience Gallery、MA、用户级分析能力及 downstream identity mapping。
English
A portion of Pulse group members are active within groups — generating messages, signals, and activities — yet their phone numbers cannot be directly retrieved by Pulse due to WhatsApp platform restrictions, user privacy settings, or community privacy configurations.

As a result, these members cannot complete identity stitching with V2 users, which impacts signal aggregation, Audience Gallery, MA, user-level analytics, and downstream identity mapping.
02

目标 ObjectivesObjectives

技术目标 Technical ObjectiveTechnical Objective
建立一套基于 LID ID 的 identity recovery pipeline，通过 手机号 → LID ID → Pulse member 匹配 的路径，恢复无法直接获取手机号的 Pulse member 身份，建立 phone ↔ LID 映射关系。
Establish an identity recovery pipeline based on LID IDs, enabling recovery of Pulse member identity via phone number → LID ID → Pulse member match, building a phone ↔ LID mapping.
业务目标 Business ObjectivesBusiness Objectives
#中文ObjectiveEnglishDetails
1提升 Pulse member 与 V2 用户之间的 identity stitching 能力Improve identity stitching between Pulse members and V2 users
2弥补 WhatsApp 平台限制导致的手机号缺失Compensate for phone number gaps caused by WhatsApp platform restrictions
3提升 Pulse signal 与真实用户之间的关联能力Improve association between Pulse signals and real users
4提升 downstream audience 与 analytics 的准确性Improve downstream audience and analytics accuracy
5为统一 Identity Resolution Framework 提供基础能力Provide foundational capability for a unified Identity Resolution Framework

4
查询 LID ID（Whapi） LID Lookup via WhapiLID Lookup via Whapi
LID Query Job 调用 Whapi API，通过手机号反查 LID ID。建议 batch query。重试策略：Retry 3 次 + exponential backoff。
失败处理：3 次重试均失败后，该手机号标记为 stitched_status: failed，保留在 mapping 表中，下次 Daily Batch 自动重新尝试。 The LID Query Job calls Whapi API to resolve LID IDs from phone numbers. Batch query recommended. Retry policy: 3 retries + exponential backoff.
Failure handling: After 3 failed retries, the phone number is marked stitched_status: failed and retained in the mapping table for automatic retry in the next Daily Batch.
ID Team — Pulse
5
Pulse Member 匹配与 Stitching Pulse Member Matching & StitchingPulse Member Matching & Stitching
Pulse 基于 LID ID 与 group member 数据完成 member 匹配，建立 phone ↔ LID 映射关系，历史 signal 归属到对应用户。 Pulse uses LID ID and group member data to complete member matching, establishes phone ↔ LID mapping, and attributes historical signals to the matched user.
ID Team — Pulse
6
同步至 BigQuery + 通知 V2 Sync to BigQuery + Notify V2Sync to BigQuery + Notify V2
Pulse 将 mapping 结果写入 BigQuery identity mapping 表（含 stitched_status）。V2 通过读取 BigQuery 获知已完成 stitching 的手机号，后续自动排除于查询列表之外。
通知机制：BigQuery mapping table 作为唯一通知渠道，不设独立 API 回调。 Pulse writes mapping results to the BigQuery identity mapping table (including stitched_status). V2 reads BigQuery to identify successfully stitched phone numbers and excludes them from future query batches.
Notification mechanism: BigQuery mapping table is the sole notification channel — no separate API callback.
ID Team — PulseCN Team — V2 reads BQ

Glossary

术语表 GlossaryGlossary

术语 / TermTerm定义 / DefinitionDefinition
LID (Linked ID)WhatsApp 为每个用户分配的平台级唯一标识符，在用户隐私设置限制手机号获取时仍可查询。A platform-level unique identifier assigned by WhatsApp to each user, queryable even when phone number retrieval is restricted by privacy settings.
Identity Stitching将来自不同系统或渠道的用户标识符（phone、LID、uid 等）关联到同一个真实用户的过程。The process of linking user identifiers from different systems or channels (phone, LID, uid, etc.) to a single real user.
phone ↔ LID mapping手机号与 WhatsApp LID ID 之间的双向映射关系，存储于 BigQuery identity mapping 表。A bidirectional mapping between a phone number and a WhatsApp LID ID, stored in the BigQuery identity mapping table.
Daily Batch Job每日自动运行一次的批处理作业，负责拉取待查询手机号、调用 Whapi、完成 stitching。An automated batch job that runs once daily to fetch pending phone numbers, call Whapi, and complete stitching.
stitched_statuspending 待处理awaiting processing · success 已完成completed · failed 失败待重试failed, pending retry
Whapi第三方 WhatsApp API 服务商，提供通过手机号查询 LID ID 的接口。A third-party WhatsApp API provider offering an endpoint to resolve LID IDs from phone numbers.
Pulse印尼团队负责的 WhatsApp group 社群管理系统，本文档中 Pulse 团队即印尼开发团队。The WhatsApp group community management system owned by the Indonesian development team (ID Team).
V2中国团队负责的核心用户系统，提供手机号查询 API 并消费 stitching 结果。The core user system owned by the Chinese development team (CN Team), providing the phone query API and consuming stitching results.
signal aggregation将 Pulse group member 的行为信号（消息、活动等）归属到对应真实用户的聚合过程。The process of attributing Pulse group member behavioral signals (messages, activities, etc.) to the corresponding real user.
exponential backoff一种重试策略，每次重试之间的等待时间按指数级递增，用于避免对外部 API 造成过大压力。A retry strategy where the wait time between retries increases exponentially, used to avoid overwhelming external APIs.
